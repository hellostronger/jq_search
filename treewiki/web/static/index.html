PAGE TYPES

四类知识页

EN
实体页wiki/entities/

公司、人物、产品等实体，聚合跨来源事实，附 claim 级引用。

TP
主题页wiki/topics/

概念、方法与主题综述，用 [[互链]] 连接相关实体与来源。

SR
来源摘要页wiki/sources/

每篇原始文档一页，结构化沉淀关键事实和页码。

AN
分析页wiki/analyses/

好答案回填形成的新知识页，让查询也成为复利资产。

STRUCTURE FILES

目录、时间线与 Wiki 树

IDX
index.mdwiki/index.md

全 wiki 内容目录：按类别组织，每页一行「链接 + 一句话摘要」。

LOG
log.mdwiki/log.md

追加式时间线，记录每次 ingest / query / lint。

SCH
SCHEMA.mdwiki/SCHEMA.md

wiki 的结构约定：命名、页面类型、互链与维护流程。

TRE
wiki_tree.jsonindex/wiki_tree.json

对整个 wiki 建的目录树，M3 用于 wiki 优先检索。

TARGET FORMAT

Wiki 页面格式示例

来自 docs/DESIGN.md，仅作格式说明，不是当前数据 
---
id: ent_disney
title: 华特迪士尼公司
type: entity
tags: [媒体, 流媒体]
sources: [src_0007, src_0003]
citations:
  - doc: src_0007
    pages: [1, 2]
    claim: "FY25 Q1 收入 $24.7B，同比 +5%"
updated: 2026-10-19
stale: false
---
正文。互链写法：[[ent_disney_plus]]、[[src_0007]]。
每个关键 claim 都带 doc + pages，可沿「Wiki 页 → 源树节点 → 原始页」下钻。

WHAT YOU WILL SEE

一次问答会展示哪些 PageIndex 产物

1定位轨迹

每一轮 LLM 在树上选择 expand / read 的节点与理由。

2读取节点

实际展开的树节点、覆盖页范围和兜底策略。

3原文证据

被读取的原始页，答案引用只能来自这些页。

4带引用答案

答案正文中的 [pX] 与结构化引用列表。

M2 接入后，级联模式会先命中 Wiki 页；当页面 stale 或问题要求原始细节时，再沿引用的源树下钻到页。
